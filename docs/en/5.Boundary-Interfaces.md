# System Boundary Interface Documentation

This document describes the system's external invocation interfaces, including CLI commands, API endpoints, configuration parameters, and other boundary mechanisms.

## Command Line Interface (CLI)

### agentwiki [PROFILE]

**Description**: A command-line tool (Rust, clap) that generates C4-style architecture documentation for a repository using already-authenticated agent CLIs (devin, claude, codex) as the LLM backend. Single entry point: `main.rs` parses `Args` with clap, merges configuration in the order defaults → `~/.config/agentwiki/config.toml` (or `$XDG_CONFIG_HOME/agentwiki/config.toml`) → `<project>/agentwiki.toml` → selected profile → CLI overrides, then runs the scan → research → compose → write → verify pipeline. SIGINT/SIGTERM handling: the first signal cancels gracefully (killing child CLIs), the second exits with code 130.

**Source File**: `src/cli.rs, src/main.rs`

**Arguments**:

- `PROFILE` (string): optional - Name of a profile predefined in a `[profiles.<name>]` section of agentwiki.toml (project or global). A project profile shadows a global one with the same name; an unknown profile errors out listing the available ones.

**Options**:

- `--project-path, -p`(path): optional - Path of the repository to document. (default: `.`)
- `--output-path, -o`(path): optional - Directory that receives the generated Markdown doc tree. (default: `./agentwiki.docs`)
- `--config, -c`(path): optional - Explicit path to an agentwiki.toml file (by default looks for `<project>/agentwiki.toml`, falling back to `agentwiki.toml` in cwd). (default: `<project>/agentwiki.toml`)
- `--target-language`(enum {zh, en, ja, ko, de, fr, ru, vi}): optional - Language for prose in the generated docs; every prompt gets the corresponding language instruction appended while JSON keys stay in English. (default: `en`)
- `--model-efficient`(string): optional - `"<backend>:<model>"` string for regular tasks (Efficient tier). (default: `devin:swe-2-medium`)
- `--model-powerful`(string): optional - `"<backend>:<model>"` string for heavy reasoning and retry fallback (Powerful tier). (default: `devin:swe-2-medium`)
- `--max-parallels`(usize): optional - Maximum number of concurrent agent CLI calls (minimum 1). (default: `2`)
- `--agentic`(flag): optional - Agentic mode: the agent reads the repo itself at the project root instead of embedding code/materials in the prompt (embedded mode is the default). (default: `false`)
- `--no-cache`(flag): optional - Do not read from or write to the on-disk cache (`.agentwiki/`). (default: `false`)
- `--force-regenerate`(flag): optional - Ignore cached results, recompute and overwrite. (default: `false`)
- `--skip-research`(flag): optional - Skip the LLM research phase; load the existing `.agentwiki/research.json`. (default: `false`)
- `--skip-documentation`(flag): optional - Stop after the research phase; do not generate/write docs. (default: `false`)
- `--dry-run`(flag): optional - Only scan the repo, print the effective config and task DAG, then exit — no LLM calls. (default: `false`)
- `--verbose, -v`(count flag): optional - Progressive log level: `-v` info, `-vv` debug, `-vvv` trace; the `RUST_LOG` env var takes precedence. (default: `0 (warn)`)

**Usage Examples**:

```bash
agentwiki -p /path/to/repo -o ./docs
```

```bash
agentwiki research -p . --skip-documentation
```

```bash
agentwiki --dry-run --model-efficient claude:sonnet -vv
```

```bash
agentwiki -c custom/agentwiki.toml --agentic --force-regenerate
```

### agentwiki.toml / ~/.config/agentwiki/config.toml (TOML configuration)

**Description**: File-based configuration interface (treated as a startup/config boundary). Every field is optional and merges over the defaults; the `[profiles.<name>]` section defines profiles selectable via the positional arg. Related environment variables: `XDG_CONFIG_HOME` (global config location) and `RUST_LOG` (overrides log level).

**Source File**: `src/config.rs`

**Options**:

- `project_path / output_path / internal_path / prompts_dir`(path): optional - Repo path, output directory, internal state directory (default `.agentwiki`, resolved relative to the project), and prompt-override directory. (default: `. / ./agentwiki.docs / .agentwiki / None`)
- `target_language`(string enum): optional - Prose language (zh|en|ja|ko|de|fr|ru|vi). (default: `en`)
- `mode`(string enum): optional - `embedded` (embed materials in prompts) or `agentic` (agent reads files itself). (default: `embedded`)
- `max_parallels`(usize): optional - Maximum parallelism of CLI calls. (default: `2`)
- `skip_research / skip_documentation / no_cache / force_regenerate`(bool): optional - Pipeline and cache control flags, equivalent to the CLI flags. (default: `false`)
- `[models] efficient / powerful`(string): optional - `"<backend>:<model>"` strings for the two model tiers (efficient for regular tasks, powerful for heavy reasoning/fallback). (default: `devin:swe-2-medium`)
- `[limits] daily_cap / call_timeout_s / retry_attempts / materials_char_cap / code_insights_limit / file_source_chars`(number): optional - Operational limits: CLI calls per day, per-call timeout, parse/validation retry count, max materials size embedded into prompts, max insights files, source chars per file in dir_summary. (default: `300 / 600 / 3 / 192000 / 25 / 500`)
- `[scan] max_depth / max_file_size / git_tracked_only / include_hidden / include_tests / excluded_dirs / excluded_files`(mixed): optional - Repo scan options: recursion depth, max file size, git-tracked-only scanning (via `git ls-files`), include dotfiles/tests, excluded directory names and file globs. (default: `10 / 524288 / true / false / false / <default list target,node_modules,vendor,...> / <*.lock,*.log,.env,agentwiki.toml,...>`)
- `[verify] mermaid_fixer`(bool): optional - Run `mermaid-fixer --dry-run` over the output tree if the binary is available; falls back to an internal heuristic when absent. (default: `true`)

**Usage Examples**:

```bash
max_parallels = 4\ntarget_language = "vi"\n[models]\nefficient = "claude:sonnet"\npowerful = "devin:swe-2-medium"\n[limits]\ndaily_cap = 50\n[profiles.research]\nskip_documentation = true
```

## Integration Suggestions

### CLI invocation / subprocess

The standard integration is invoking the `agentwiki` binary as a subprocess. Use `--dry-run` to check the effective config and DAG before a real run; expect exit code 130 when cancelled via SIGINT/SIGTERM.

**Example Code**:

```
#!/usr/bin/env bash
agentwiki -p "$REPO" -o "$OUT" --target-language vi --model-efficient claude:sonnet 2>&1 | tee run.log
# or check first:
agentwiki -p "$REPO" --dry-run -v
```

**Best Practices**:

- Always run `--dry-run` first in CI/cron to avoid burning agent CLI quota.
- Set `daily_cap` under `[limits]` to protect subscription quota; inspect `.agentwiki/` (cache, quota, calls.jsonl audit log) after each run.
- Do not pass API-billing env vars (OPENAI_API_KEY, ANTHROPIC_API_KEY…) to the process — agentwiki already strips billing variables when spawning backends; keep the caller side clean as well.
- Build once with `cargo build --release`; use `--max-parallels` cautiously since each slot is a heavy CLI subprocess.

### Library (Rust crate)

The `agentwiki` crate (lib + binary) can also be used directly: `Config::load(&CliOverrides, path)`, `PipelineCtx::new(config, cancel)`, `agentwiki::run(&pctx)`, or `scanner::scan` + `dry_run_report`. Suitable for embedding into a larger tool or substituting `MockBackend` for offline tests.

**Example Code**:

```
let overrides = CliOverrides::default();
let config = Config::load(&overrides, None)?;
let pctx = agentwiki::PipelineCtx::new(config, None).await?;
agentwiki::run(&pctx).await?;
```

**Best Practices**:

- Pass a `CancellationToken` instead of `None` to cancel proactively from the caller.
- Use `MockBackend` (via the `mock:*` model string or a custom `AgentBackend` trait impl) to test the pipeline without a real agent CLI.
- Keep a separate `internal_path` per repo so caches/quotas don't mix.

### External tool contract

External dependencies follow loose contracts: the `devin|claude|codex` backend must be a pre-authenticated CLI on PATH (invoked as `devin -p`, `claude -p`, `codex exec`); `git` is optional for `git ls-files`; `mermaid-fixer` is optional for the verify phase.

**Example Code**:

```
# check availability before running
command -v devin claude codex git mermaid-fixer
```

**Best Practices**:

- Ensure the agent CLI is logged in on a subscription first — agentwiki does not manage authentication.
- If `mermaid-fixer` is absent, the system falls back to the internal heuristic; installation is not mandatory.
- For non-git repos, set `scan.git_tracked_only = false` and provide suitable `excluded_dirs`.
