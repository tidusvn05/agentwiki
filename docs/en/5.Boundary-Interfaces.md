# System Boundary Interface Documentation

This document describes the system's external invocation interfaces, including CLI commands, API endpoints, configuration parameters, and other boundary mechanisms.

## Command Line Interface (CLI)

### agentwiki [PROFILE]

**Description**: Main entry point: scans a target repository, orchestrates a DAG of LLM analysis agents via locally installed agent CLIs (devin, claude, codex), and writes C4-style architecture documentation under the repo's .agentwiki/ directory. PROFILE is a named profile from agentwiki.toml / ~/.config/agentwiki/config.toml ([profiles.<name>]), or a backend name (devin, claude, codex) to select that CLI's default models.

**Source File**: `src/cli.rs (Args), src/main.rs`

**Arguments**:

- `PROFILE` (string): optional - Named config profile or backend name (devin|claude|codex). Any first token that is not a subcommand is read as PROFILE.

**Options**:

- `--project-path, -p`(path): optional - Repository path to document. (default: `current directory`)
- `--output-path, -o`(path): optional - Documentation output directory.
- `--config, -c`(path): optional - Path to agentwiki.toml (defaults to <project>/agentwiki.toml). (default: `<project>/agentwiki.toml`)
- `--target-language`(enum (zh|en|ja|ko|de|fr|ru|vi)): optional - Documentation language.
- `--model-efficient`(string): optional - "<backend>:<model>" for routine tasks.
- `--model-powerful`(string): optional - "<backend>:<model>" for heavy reasoning / retry fallback.
- `--max-parallels`(integer): optional - Max concurrent CLI calls.
- `--agentic`(flag): optional - Let the agent read the repo itself instead of embedding code in prompts. (default: `false`)
- `--no-cache`(flag): optional - Do not read or write the on-disk cache. (default: `false`)
- `--force-regenerate`(flag): optional - Ignore cached results; recompute and overwrite them. (default: `false`)
- `--skip-research`(flag): optional - Skip the research phase; load .agentwiki/research.json. (default: `false`)
- `--skip-documentation`(flag): optional - Stop after the research phase (no documentation written). (default: `false`)
- `--dry-run`(flag): optional - Print the resolved config and task DAG, then exit. (default: `false`)
- `--verbose, -v`(count flag): optional - Verbose logging (-v info, -vv debug, -vvv trace); RUST_LOG env var overrides. Global flag, also applies to subcommands. (default: `0 (warn)`)

**Usage Examples**:

```bash
agentwiki -p /path/to/repo
```

```bash
agentwiki claude -p . --model-efficient claude:haiku --model-powerful claude:opus
```

```bash
agentwiki myprofile --agentic --max-parallels 8 -vv
```

```bash
agentwiki --dry-run -p .
```

### agentwiki doctor

**Description**: Health-check the environment: agent CLIs on PATH, running or orphaned agent processes, .agentwiki/ state, config sanity. Read-only; does not take the run lock.

**Source File**: `src/cli.rs (DoctorArgs), src/doctor.rs`

**Options**:

- `--project-path, -p`(path): optional - Repository path to inspect (defaults to top-level -p or cwd). (default: `top-level -p or cwd`)
- `--config, -c`(path): optional - Path to agentwiki.toml (defaults to top-level -c).
- `--fix`(flag): optional - Also clean up: remove a stale run.lock and leftover tempfiles. (default: `false`)

**Usage Examples**:

```bash
agentwiki doctor
```

```bash
agentwiki doctor -p /repo --fix
```

### agentwiki drift

**Description**: Check generated core_dependencies claims against a statically extracted import graph. Read-only; exits 1 only under --strict. Suitable for CI gating on documentation drift.

**Source File**: `src/drift/mod.rs (DriftArgs), src/cli.rs (Command::Drift)`

**Options**:

- `--project-path, -p`(path): optional - Repository path to check (inherits top-level -p). (default: `top-level -p or cwd`)
- `--config, -c`(path): optional - Path to agentwiki.toml (inherits top-level -c).
- `--output-path, -o`(path): optional - Output/state directory (inherits top-level -o).
- `--claims`(path): optional - Path to the core_dependencies claims JSON file to verify.
- `--baseline`(path): optional - Path to a baseline file of known findings to suppress.
- `--max-depth`(integer): optional - Maximum graph depth to analyze (N).
- `--strict`(flag): optional - Exit with code 1 when findings are present (CI gating). (default: `false`)
- `--update-baseline`(flag): optional - Write current findings to the baseline file to suppress them in future runs. (default: `false`)
- `--export-claims`(path): optional - Export the extracted claims to a PATH for inspection.
- `--json`(flag): optional - Emit machine-readable JSON report (drift.json) instead of text. (default: `false`)

**Usage Examples**:

```bash
agentwiki drift -p . --json
```

```bash
agentwiki drift --strict --baseline drift-baseline.json
```

```bash
agentwiki drift --update-baseline
```

### agentwiki.toml / ~/.config/agentwiki/config.toml (configuration file boundary)

**Description**: TOML configuration merged with CLI overrides (CLI wins). Sections include [models] (efficient/powerful backend:model), [limits] (e.g. max_parallels, daily quota), [scan] (file scanning options), [verify], [profiles.<name>] named profiles that bundle settings, plus drift configuration (claims/baseline paths, thresholds). Global config resolved via XDG_CONFIG_HOME or home dir.

**Source File**: `src/config.rs, src/drift/config.rs`

**Options**:

- `profiles.<name>`(table): optional - Named profile selectable via the PROFILE positional argument; can shadow global settings.
- `models.efficient / models.powerful`(string): optional - Backend:model pairs for routine vs. heavy-reasoning agent tasks.
- `limits.* / scan.* / verify.* / drift.*`(tables): optional - Concurrency limits, quota, scanner settings, verification and drift-check settings; partial sections merged over defaults.

**Usage Examples**:

```bash
[models]
efficient = "claude:haiku"
powerful = "devin:default"

[profiles.fast]
max_parallels = 8
```

### Environment variables

**Description**: Env-var interface: RUST_LOG overrides the -v verbosity ladder via EnvFilter; XDG_CONFIG_HOME/HOME locate the global config; PATH is searched for devin/claude/codex binaries; AGENTWIKI_E2E=1 opts into the real-CLI e2e test suite.

**Source File**: `src/main.rs (init_tracing), src/config.rs, tests/e2e_real_cli.rs`

**Options**:

- `RUST_LOG`(filter string): optional - tracing EnvFilter; overrides -v/-vv/-vvv. (default: `agentwiki=warn`)
- `XDG_CONFIG_HOME`(path): optional - Base directory for global agentwiki config lookup. (default: `~/.config`)
- `AGENTWIKI_E2E`(string): optional - Set to 1 to run ignored e2e tests that invoke real agent CLIs.

**Usage Examples**:

```bash
RUST_LOG=agentwiki=debug agentwiki -p .
```

```bash
AGENTWIKI_E2E=1 cargo test --test e2e_real_cli
```

## Integration Suggestions

### Subprocess (agent CLI backend)

agentwiki shells out to locally installed, subscription-authenticated agent CLIs as its LLM backends. devin and claude receive the prompt on stdin with -p; codex runs `codex exec` with --output-schema and emits a line-based event stream. claude returns a JSON envelope parsed for text, structured output, and token usage.

**Example Code**:

```
echo "$PROMPT" | claude -p
echo "$PROMPT" | devin -p
codex exec --output-schema schema.json < prompt.txt
```

**Best Practices**:

- Authenticate each backend CLI via its own subscription auth before running agentwiki; run `agentwiki doctor` to verify they are on PATH.
- Use --max-parallels and the daily quota to bound concurrent subprocess calls and cost.
- Implement new backends behind the AgentBackend trait (for_kind factory) rather than calling CLIs directly.

### CI invocation (drift gating)

Run `agentwiki drift` in CI to compare documented dependency claims against the real static import graph. Use --json for machine-readable drift.json and --strict for a non-zero exit code when findings exist; --baseline/--update-baseline suppress known findings.

**Example Code**:

```
agentwiki drift -p . --json --strict --baseline .agentwiki/drift-baseline.json
```

**Best Practices**:

- Commit a baseline file and update it deliberately via --update-baseline, not automatically.
- Drift is read-only and safe to run in CI; it never writes pipeline state.
- Generate docs first so the claims file exists before running drift.

### Binary installation (HTTP download)

install.sh downloads prebuilt agentwiki binaries from GitHub Releases via curl, mapping the host platform to Rust target triples. The crate is also published to crates.io.

**Example Code**:

```
curl -fsSL https://github.com/<org>/agentwiki/releases/latest/download/install.sh | sh
# or
cargo install agentwiki
```

**Best Practices**:

- Pin a release version in automated installs rather than latest.
- Verify checksums/signatures where provided before piping to sh.

### Prompt template override (data-driven customization)

Embedded markdown prompt templates under prompts/ and prompts/editors/ can be overridden on disk without recompiling; templates support {{custom}} interpolation slots for per-project dossier/context injection.

**Example Code**:

```
mkdir -p prompts/editors
cp <override>.md prompts/editors/architecture_doc.md
```

**Best Practices**:

- Keep Mermaid safety rules intact when overriding editor prompts.
- Template variables are not compile-time checked — verify with --dry-run or a small run first.
